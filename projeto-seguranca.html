Segurança

De TriânguloLeaks, a enciclopédia do Triângulo Mineiro

Esta página descreve, sem jargão e sem promessas vagas, como este site é protegido — e também onde estão os seus limites. A TriânguloLeaks é um site estático: isso elimina classes inteiras de risco (não há banco de dados para vazar, nem painel administrativo para invadir), mas exige cuidado com o que roda no navegador de quem lê.

1. Política de segurança de conteúdo (CSP)

Toda página declara uma CSP restritiva. A linha de base, presente em todas elas, é: 

default-src 'self'; img-src 'self' data:; frame-src 'self' https://www.google.com; style-src 'self' 'unsafe-inline';
script-src 'self'; form-action 'self'; base-uri 'none'; object-src 'none'

Na prática, isso significa:

  • Nenhum script inline. Todo comportamento do site vive em arquivos .js próprios — por isso não existe um único onclick= no HTML. É a defesa mais eficaz contra injeção de script (XSS).
  • Nenhum script de terceiros por padrão. Só as páginas que realmente precisam (login e mapas) ampliam a política, e apenas para os domínios exatos daquele recurso.
  • form-action 'self': mesmo que alguém conseguisse injetar um formulário, ele não poderia enviar dados para fora do site.
  • base-uri 'none' e object-src 'none': bloqueiam duas técnicas clássicas de sequestro de links relativos e de plugins antigos.

Além da CSP, toda página declara <meta name="referrer" content="no-referrer">: quando você clica num link externo, o outro site não recebe a informação de qual artigo você estava lendo.

2. O que é carregado de fora

O site é autocontido, com três exceções declaradas:

RecursoOnde apareceProteção aplicada
Mapas incorporados do Google Maps Seção Localização dos artigos frame-src limitado ao domínio do Google Maps; o iframe usa sandbox (sem permissão de navegar a página principal nem enviar formulários), referrerpolicy="no-referrer" e loading="lazy"
Fotografias hospedadas no Wikimedia Commons 15 artigos que têm foto real licenciada img-src ampliado apenas naquelas páginas, e só para commons.wikimedia.org
Bibliotecas de login (Google, Microsoft/MSAL, Apple) Somente Entrar e Criar conta script-src e connect-src ampliados só nessas duas páginas, e só para os domínios oficiais de cada provedor

Nenhum desses recursos é um rastreador: não há analytics, pixel, fonte remota nem CDN de estilo. Se um deles estiver bloqueado ou fora do ar, a página continua legível.

3. Autenticação
  • Chave de acesso (Passkey/WebAuthn) — autenticação real, sem senha, apoiada no seu dispositivo (Face ID, Touch ID, Windows Hello ou chave física). A chave privada nunca sai do seu aparelho.
  • Google, Microsoft (Outlook) e Apple — autenticação real por OAuth / OpenID Connect quando o administrador preenche as credenciais em js/login-config.js. O site verifica o token recebido: no caso do Google, contra o endpoint oficial de verificação; no caso da Apple, conferindo a assinatura criptográfica contra as chaves públicas publicadas pela própria Apple (via Web Crypto); no caso da Microsoft, conferindo o destinatário declarado no token. Enquanto não houver credencial configurada, o botão diz claramente que não está configurado — ele nunca finge ter autenticado alguém.
  • Protonmail — permanece uma simulação rotulada, porque não existe um serviço público de Login com Proton para sites de terceiros. Preferimos dizer isso na cara do que imitar um fluxo real.
  • Login local — o modo de demonstração aceita qualquer e-mail e nunca grava a senha digitada (há teste automatizado verificando isso).

4. Dados de quem usa

Tudo o que o site guarda fica no localStorage do seu próprio navegador, com o prefixo tp: — inclusive o perfil de leitura usado para sugerir artigos. A página de Privacidade lista item por item o que está guardado agora e traz botões para baixar uma cópia ou apagar tudo.

Como não há servidor, também não há: banco de dados de usuários, senhas armazenadas, logs de acesso centralizados, nem backups fora do seu dispositivo.

5. Limites conhecidos (o que este site não protege)
  • Quem controla o navegador vê os dados locais. Qualquer pessoa com acesso ao seu computador e ao seu perfil de navegação pode ler o que está no localStorage. Em computador compartilhado, use uma janela anônima ou apague os dados ao terminar.
  • A CSP em <meta> não cobre tudo. Diretivas como frame-ancestors (proteção contra clickjacking) e cabeçalhos como Strict-Transport-Security e X-Content-Type-Options só funcionam quando enviados pelo servidor web. Quem publicar este site deve configurá-los na hospedagem — a CSP embutida aqui é o máximo que um arquivo estático consegue declarar sozinho.
  • Integridade de sub-recursos (SRI) não é aplicada às bibliotecas de login: Google, Microsoft e Apple publicam esses arquivos sem hash estável, e fixar um hash quebraria o login a cada atualização deles.
  • Este site não é fonte para decisões jurídicas, médicas ou financeiras, e seu conteúdo histórico traz marcações [verificar] onde a confirmação ainda não foi possível.

6. Como relatar um problema

Encontrou uma falha de segurança, um link malicioso ou um dado indevidamente exposto? Escreva pela Central de ajuda, descrevendo o passo a passo para reproduzir. Problemas de conteúdo (data errada, fonte fraca) podem ser relatados do mesmo jeito — ou corrigidos por você mesmo pelo botão Editar de cada artigo.
